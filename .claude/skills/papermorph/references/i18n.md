# Languages

Three different things are called "language"; keep them apart.

1. **The book's language**: narration, captions, on-screen text and chapter files. Set in `style.json` (`book.language`, e.g. `es`), `CHAPTER.language` and the audio
   folder `audio/<lang>/`, and `<html lang>` of every page. A book has one language; lessons are never translated by the platform.
2. **The interface language**: player buttons, cover and contents, the tutor panel, the learning screens. Switchable per user.
3. **The tutor's answer language**: always the language of the learner's last message (so a Spanish book can be questioned in English and the other way round); for very
   short messages the interface language decides. When it answers in another language than the lesson it adds the lesson's term in parentheses the first time.

## Interface language

`lib/lang.js` (first script on every page) offers the book's language, English, and anything in `window.UI_LANGS`; the choice is stored per browser (and per user in login mode),
shown as a pill (`ES | EN | ...`, top left in lessons, top right on the cover) and applied by reloading the page (a lesson reopens at the same scene and second).
`UILang.t(spanish, english)` is how every UI string is written. To add a language, define before `lang.js` (a `<script>` in each page, or a small `lib/i18n-extra.js`):

```html
<script>
  window.UI_LANGS = ['pt'];
  window.UI_STRINGS = { pt: { 'Notas': 'Notas', 'Enviar': 'Enviar', 'Ejemplo': 'Exemplo' /* key = the Spanish text used in the code */ } };
</script>
<script src="../lib/lang.js"></script>
```

A missing key falls back to English (Spanish for `es`). The Spanish text in the code is the key; `grep -o "tr('[^']*'" lib/tutor.js lib/learn.js lib/lang.js` lists them. The player's own text (engine) has
English and Russian built in; Spanish ships as `lib/es.js` (installed automatically for Spanish books, `EsBook.contents()` handles the cover); for another language write an engine table
like `es.js` (`TRANSLATIONS.<lang> = {...}`) and, best, contribute it to the engine source. `UILang.speech()` gives the locale for voice input/read-aloud (`pt-BR`, `fr-FR`, ...).

## Narration language and pronunciation

`tts.py` voices `content/<book>/chNN/narration.<lang>.json`. Pick the voice and rate in `style.json` `voice`. **Respellings** (`narration.say`, merged into `style.json` `voice.say` by
`scripts/merge_say.py`) exist to make a narration sound right when it mixes languages or reads acronyms and symbols, e.g. an English term inside Spanish narration. Use them **only when the
book's language needs them**; they are off (empty) by default. Rules that cost revisions: whole-word, case-sensitive; never add a bare single letter or a common word as a key (a Spanish "Y" at the start of a
sentence once became "uai"); prefer spelling acronyms as letter names; re-voicing changes timings, so re-run the e2e test and the leftover finder; nobody listens to the audio while building, so ask the user
to spot-check respellings.

## Terms in a bilingual learning setup

If the learner needs the foreign term for work (a Spanish book that teaches English vocabulary), use "term (English term)" at first mention, then the English term, plus a small tag beside the term on screen and a
bilingual `## Glossary` per chapter. The tutor reads that glossary and keeps the convention. Put the rule in `style.json` `words` and in `tutor.md`.
